# LZ77 experiment: 100-image comparison (2026-11-10)

## Decision

No broad single-thread slowdown was observed in this sample. The final LZ77
experiment reduced the summed native encoding medians by 1.15% at one thread
and 0.69% at eight threads, with unchanged sizes and exact official-decoder
pixel reconstruction. These are small measured differences, not evidence of
a universally faster implementation. Keep `experimental-lz77-hotspots`
**disabled by default**; no encoder implementation or default was changed
during this test.

The earlier rough-linen MA attribution is not supported by this corpus test.
This run measures whole native encodes, not MA-exclusive or LZ77-exclusive
CPU time. It cannot attribute a small elapsed-time change to a particular
kernel. See [the experiment and MA timing correction](LZ77_MATCH_PRICE_20261110.md).

## Scope And Reproduction

- Windows x86_64, native Rust pixel-lossless encoding, effort 9.
- Same fixed projected backend policy in both executables; default palette
  ordering, patches disabled, no outer `searchbest` candidate search.
- Compare the pre-change Rust binary with the final combined experiment,
  including the length-cache boundary and unused-route guards. This is **not**
  the intermediate `palette-combined.exe` used in the earlier MA retest,
  nor a speed comparison against C++ libjxl 0.12.
- Binaries were frozen; no builds or concurrent encoder benchmarks ran during
  measurements. Inputs were not cropped, resized or re-encoded for convenience.
- Each of the 100 inputs: two measured trials per executable per thread count,
  alternating order; no discarded warmups in the initial screen. The two-value
  median equals their arithmetic mean. All observations remain in the reports.
- Single-thread and eight-thread passes ran sequentially. Native-call timers
  exclude process startup, PNG IO, independent decoding and pixel comparison.
- Profiling was disabled in every run in this report. No sums of inclusive
  parallel profile scopes are presented as wall-time speedups.
- Every encoded output was decoded with official libjxl 0.12 `djxl` and checked
  against the original sample values, including hidden RGB. Encoded JXL byte
  identity was not a requirement. Sizes being unchanged is an observation.
- This is a shared-workstation, two-repeat screen with targeted follow-up,
  not a frequency-locked laboratory benchmark or a full-corpus guarantee.

## Interpretation

- The broad result does not support treating the earlier one-image timing
  as a general single-thread performance regression.
- It also does not justify promoting a sub-1.2% aggregate difference as a
  robust default speedup. The same caution applies to favorable outliers.
- These changes target match extension, compiled length prices and limited
  DP pruning. They do not replace MA learning, transforms, tokenization or
  entropy coding. Their local kernel savings need not dominate a whole
  encode. This is a scope limitation, not a measured stage-level explanation
  for any particular image in this uninstrumented screen.
- The compatible codestream and pixel checks pass on these inputs. No
  compressed-byte identity target or lowered effort/search budget was used.
- No compiler-layout, CPU-frequency, allocator or scheduling explanation is
  established here. Stage attribution needs its own controlled experiment;
  a maximum MA elapsed scope alone cannot provide it.
