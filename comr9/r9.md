先修一个默认值冲突：r9 的自动分条上一轮改成了 10/12（为轻量档调的），但完整 48 上下文档仍应保持 2–4 条，否则会分配几十 GB 的表。让分条数按“模型重量”自动切换。

## 两个版本的区别

同一套编解码器（`r9-parapipe` / `r8-pipeline`），区别完全由模型参数决定：

| 参数 | 完整版（比率优先） | r9-fast（速度优先） |
|---|---|---|
| 上下文数 | 48（44 deepmix + 4 动画） | 12（8 + 4） |
| 混合器 / 更新数 | 7 / 48 | 2 / 12 |
| 桶宽 / 表 stride | 12-bit / 48 | 8-bit / 12 |
| 每模型表大小 | ~100 MB | **1.57 MB** |
| 预取 | 开（1 行） | **关** |
| 学习率 / 第二选择器 | lr=3 / 公式 1 | lr=5 / 公式 3 |
| 色度分支 | 自动（score+试编码） | 强制绝对 |
| 自动分条 | 2–4 条 | ≤1.5MP 10 条，否则 12 条 |
| 三图结果 | 2,590,066 B / 48.4 s（r8） | **3,038,939 B / 2.20 s** |
| 定位 | 比 deepmix 小 0.59%、快 2.08× | 比 minimix 小 1.14%、快 5.2% |

## 如何运行

先构建：

```bash
cd /d/rust_projects/image_compress2
cargo build --release
```

### 1) r9-fast（超过 minimix 的那档）

```bash
ACM_NCTX=12 ACM_MIX=2 ACM_UPD=12 ACM_SEL2=3 R4_LR=5 \
R8_SELECT=abs ACM_BUCKET_BITS=8 ACM_PREFETCH=0 \
./target/release/animebench.exe --codec r9-parapipe --iters 3
```

预期：A 442,529 B / ~0.32 s，B 759,503 B / ~0.52 s，C 1,836,907 B / ~1.35 s，合计 **3,038,939 B / 2.20 s**。

指定分条数：

```bash
... R9_TILES=12 ./target/release/animebench.exe --codec r9-parapipe --match 3FFEDE
```

### 2) 完整版 r8（比率优先，对比 deepmix）

```bash
./target/release/animebench.exe --codec r8-pipeline
```

默认即报告配置：48ctx、mix7、12-bit、预取开、自动色度分支。预期合计 **2,590,066 B / ~48 s**。

### 3) 完整版 r9（并行全模型，4.26× deepmix）

```bash
./target/release/animebench.exe --codec r9-parapipe
```

默认自动 2/2/3 条（48ctx 重模型）。预期 **2,613,769 B / ~23.6 s**。

### 4) 单图 / 严格校验

```bash
# 只跑一张（文件名前缀匹配）
./target/release/animebench.exe --codec r9-parapipe --match 3FFEDE

# 不做逐字节比较（仍然完整解码，只是跳过比对），适合测时间
--no-verify

# 严格 roundtrip 校验：不加 --no-verify
./target/release/animebench.exe --codec r9-parapipe --iters 1
```

> 注意：**解码必须使用与编码相同的环境变量**。容器只存了色度分支 flag 和分条数 `k`，不存 nctx/mix/lr。这是实验档位，不是自描述格式。
